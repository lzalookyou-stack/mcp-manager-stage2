# 阶段 1 — 分阶段实施计划

> 每个阶段都要求：**真实运行测试 → 如实报告结果 → 提交 Git → 上传到本阶段独立的新仓库**。
> 严禁：伪造仓库数据、测试结果、执行成功状态或安全结论。

---

## 阶段 1：调研与技术选型（本阶段）

**交付物**
- `docs/research.md`：6 个候选仓库实测调研（已验证事实 / 推断 / 未检查 / 无法确定）。
- `docs/architecture.md`：分层架构、统一插件模型、评分规则、事务状态机、威胁模型摘要、选型结论。
- `docs/plan.md`：本文件。
- `scripts/research_github.py` + `scripts/research_result.json`：可复现的调研工具与原始数据。

**验证方式**：脚本可重跑并产出相同结构的数据；6 个仓库均返回真实字段（无伪造）。

**已知缺口**：见 `docs/research.md` 第 3 节（`mcp` SDK API 形态、agentbridge scanner 实现等为「未检查」）。

---

## 阶段 2：最小可运行骨架

**范围（刻意保持最小，不引入不必要复杂度）**
1. FastAPI 后端，**默认仅监听 `127.0.0.1`**，含 Host/Origin 校验、CSRF 与会话校验骨架。
2. SQLite 持久层：插件元数据、任务状态、操作历史。
3. 统一插件数据模型（字段见 `docs/architecture.md` 第 2 节）。
4. **适配器接口**：新增插件类型无需重写核心逻辑。
5. 原生 HTML/CSS/JS 网页骨架（总览页 + 路由占位）。
6. 基础单元测试并**真实运行通过**。

**验收**：`pytest` 全绿；`python -m app` 或 `uvicorn` 可真实启动并响应 `/api/health`。

**依赖**：`fastapi`、`uvicorn`、`mcp==2.3.0`、`pytest`（版本在 `requirements.txt` 锁定）。

## 阶段 3：GitHub 搜索 / 项目分析 / 质量评分 / 安全审查

1. **搜索**：把自然语言需求（如「轻量、支持长期记忆、依赖少的 MCP 项目」）转化为 GitHub 查询；支持关键词、按维护状态/许可证/语言/规模筛选；查看 README / 提交 / Release / 依赖清单；**固定到具体 commit**；候选对比；保存候选列表与分析结果；**显示数据获取时间与缺失字段**。
   - 优先 GitHub 官方 API；限流/网络失败/权限不足**必须显式展示错误**，绝不虚构结果。
2. **质量评分**：权重 维护 20% / 质量与测试 25% / 安全 30% / 兼容 15% / 社区与许可证 10%；每项可追溯证据；Star 仅辅助；**严重安全风险不可被抵消**；区分四种证据等级。
3. **安全审查**：检查安装脚本与调用链、shell/PowerShell 执行、任意文件读写删、可疑外联、API Key/环境变量/SSH 密钥访问、安装后自动执行、动态下载执行未固定版本代码、依赖与供应链风险、Hook/启动脚本/持久化；**给出文件路径、代码位置、风险原因与证据**；**不得输出「绝对安全」「无恶意代码」等无依据结论**。
4. 测试覆盖：GitHub API 失败与限流、不完整/无效仓库信息、恶意安装脚本识别。

---

## 阶段 4：本地网页控制台交互

1. **总览**：已安装数量、运行状态、待确认操作、失败任务、最近变更。
2. **发现**：搜索/筛选/排序/分页/收藏/对比；列表显示名称与仓库链接、类型、最近更新、许可证、版本或 commit、评分及依据、风险级别、依赖与兼容性、安装状态。
3. **详情**：README 摘要、源码入口、安装要求、依赖、许可证、质量报告与风险证据。
4. **已安装**：状态与版本、安装位置与配置、启用/禁用/更新/卸载、依赖关系、最近操作与日志、可回滚版本。
5. **任务与历史**：进度、日志、结果、错误、时间、关联快照；**SSE** 推送进度与日志。

**硬性要求**：所有关键按钮连接**真实后端逻辑**并正确展示成功/失败/进行中；客户端配置读写**必须走专用适配器**，不假设不同 AI 客户端格式一致。

---

## 阶段 5：安全安装闭环

1. **安装确认页面**：展示来源与固定版本、实际命令与参数、将创建/修改/删除的文件、目标目录与配置、所需权限与运行时要求、脚本审查结果、是否联网/起进程、失败处理与回滚方案；提供取消/返回修改/确认执行；**计划变化必须重新确认**。
2. **强制安全控制**：默认仅 `127.0.0.1`；校验 Host/Origin；CSRF + 会话；凭据不暴露给前端/日志/MCP；有副作用操作必须经用户**通过受信任网页**明确授权；确认须绑定 操作 ID / 目标插件 / 固定来源与版本 / 目标路径 / 具体命令与参数 / 文件变更摘要 / 权限范围 / 计划摘要 / 过期时间；执行前重新验证；计划不一致立即拒绝；**禁止 Agent 自造或伪造授权**。
3. **命令执行**：结构化参数；**禁止 `shell=True` 与字符串拼接**；限制工作目录/环境变量/超时/输出大小；默认禁止任意安装脚本自动执行；高风险代码优先隔离；**不以正则或提示词作为安全控制**。
4. **文件系统**：路径规范化与越界检查；防路径遍历、符号链接逃逸、意外覆盖；安装前变更清单与快照；受管配置原子写入；失败恢复；禁止默认递归删除未知目录；仅回滚本系统记录并拥有的变更。
5. **回滚与事务**：持久化状态机（见架构文档第 4 节）；10 步安装流程；崩溃后可检查未完成事务，**绝不把中断标记为成功**；卸载仅处理有明确归属记录的文件。

## 阶段 6：插件适配器

优先支持 **Skill、Rules 等文件型插件**，再实现 **MCP Server** 与其他 Agent 插件；**逐类验证真实客户端配置格式**。

## 阶段 7：MCP 集成

使用官方 Python MCP SDK 暴露工具，**与网页共用同一套业务服务**（禁止两套逻辑）。初始工具：
`search_projects`、`inspect_project`、`compare_projects`、`get_install_plan`（只生成计划不执行）、`list_installed`、`inspect_plugin`、`request_operation`、`get_operation_status`、`list_operation_history`。
如增加确认工具，必须验证确认令牌、操作摘要与有效期。**不为追求工具数量过度拆分接口。**

## 阶段 8：完整测试与交付

- 运行全部静态检查、单元测试与端到端测试，覆盖全部需求场景与前后端核心流程；修复发现的问题并**如实报告真实运行结果**。
- 交付：可运行源码与目录结构、依赖锁定与安装说明、本地启动命令、MCP 客户端接入配置示例、网页操作说明、插件适配器开发说明、安全策略与威胁模型、备份与恢复说明、自动化测试与真实结果、已知限制与后续计划。
- **验收以真实运行与测试结果为准，不以代码或功能数量为准。**

---

## 贯穿全程的纪律

1. **不伪造**：仓库数据、测试结果、执行状态、安全结论都必须可复现。
2. **证据分级**：所有结论标注【已验证】/【推断】/【未检查】/【无法确定】。
3. **不以正则/提示词当安全控制**；不为通过测试而删除安全检查或降低断言。
4. **每阶段独立仓库**：本阶段成果提交并推送到一个新的独立 Git 仓库，记录地址与提交哈希。
5. **内存纪律**：测试串行执行（`-p no:cacheprovider`），避免 OOM。
